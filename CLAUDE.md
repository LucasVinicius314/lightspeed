# Lightspeed

Godot 4.7.2 (C#, Forward+, Jolt) simulation where physics runs in the present but the *visuals* are delayed by the finite speed of light. See [plan.md](plan.md) for goals, architecture, controls, milestones and status.

## Layout

- `src/Core` sim clock, speed ladder, main scene script. `src/History` recording, texture packing, retarded solver. `src/Visuals` delayed visuals and mesh tessellation. `src/Physics` speed limiter. `src/Player` camera. `src/Ui` HUD and settings menu. `src/Debug` overlays, debug modes and dev tools. `src/Demo` test motions and spawners. `src/Net` multiplayer (see below); `libs/p2p-signaling-server` is a git submodule of the signaling server repository, whose C# client is compiled into this assembly. Namespaces mirror folders (`Lightspeed.History`, ...).
- `shaders/`, `scenes/` (`scenes/objects/` for reusable objects: orbiting cube, oscillating sphere, bouncing ball, teleporting cube, car, helicopter, standing fan), `assets/`.
- `tests/Lightspeed.Tests` xUnit project. It *links* these engine-free files instead of referencing the Godot project, so they must stay free of Godot types (System.Numerics / BCL only): `src/History/RetardedSolver.cs`, `src/History/RetardedRay.cs`, `src/History/HistoryTrack.cs`, `src/Core/SpeedLadder.cs`, `src/Debug/LightRings.cs`, `src/Visuals/TessellationMath.cs`. A new engine-free file needs a `<Compile Include=... Link=...>` line in the test csproj.

## Commands

`<godot>` below is the Godot 4.7.2 mono *console* executable (its location is machine-specific; see the user's global notes).

- Build: `dotnet build Lightspeed.csproj`
- Tests: `dotnet test tests/Lightspeed.Tests`
- Multiplayer needs the WebRTC native extension in `addons/webrtc_native` (git-ignored, about 90 MB): run `bash scripts/fetch-webrtc.sh` (or `scripts\fetch-webrtc.ps1`) once after cloning. The build scripts and the release workflow refuse to run without it.
- Players download releases with the dependency-free one-liners in [README.md](README.md), which fetch `releases/latest/download/Lightspeed-windows.zip` / `Lightspeed-linux.tar.gz` from GitHub. The asset names must match what `build.ps1 -Package` produces (the tarball holds the contents directly, with no wrapping folder; the README extracts it with `-C Lightspeed`); publishing steps are in BUILDING.md.
- Releases are cut by pushing a tag `v*` on a commit that is on `main`: (every tag becomes a full release, never a pre-release, so use plain `vX.Y.Z` tags rather than `-rc`; `releases/latest` skips pre-releases and the README one-liners would 404) `.github/workflows/release.yml` runs the unit tests, builds with `build.sh --package` and publishes the two assets with `gh release create`. Godot and the two export templates are downloaded from the official release (SHA-512 checked) and cached; keep `GODOT_VERSION` in the workflow in step with the local Godot. The default branch is `main`.
- **Updater:** `scripts/update/` (`Update.bat` + `update.ps1`, `update.sh`) is copied into each build folder with a `version.txt` by `build.ps1` / `build.sh`, so an unpacked game updates itself from the latest GitHub release (tag compared with `version.txt`, asset names as above, `data_*` replaced). The scripts must not break when they overwrite themselves mid-run (one-line .bat, ps1 parsed up front, bash wrapped in a function ending in `exit`, renamed into place). Keep them dependency-free like the README one-liners.
- Release builds for Windows and Linux: `build.ps1` (or `./build.sh`), see [BUILDING.md](BUILDING.md). Presets are in `export_presets.cfg`; output goes to the git-ignored `build/`. It finds Godot through `-Godot`, `$GODOT`, a git-ignored one-line `.godot-path` file, or PATH, and needs the matching export templates (`-InstallTemplates`).
- Import / load-error check: `<godot> --headless --path . --import`
- Headless smoke test: `<godot> --headless --path . --quit-after 1000` (the shader is not exercised headless; use a window for rendering checks)
- Visual check (needs a window): `<godot> --path . -- --screenshot=<file.png>`. Options after `--`:
  - `--cpu` CPU solve instead of the shader; `--c=<m/s>` starting speed of light; `--cam=x,y,z,yawDeg,pitchDeg` camera placement.
  - `--at-tick=N` tick to capture (counted from the starting tick); `--start-tick=N` start the clock late (precision / tick-wrap test).
  - `--mode=fly|drone|walk` camera mode; `--throw=N` throw N physics objects at start; `--pause-at-tick=N` freeze the clock at tick N; `--menu-tab=<name>` with `--open-menu`.
  - `--stress=N` drop N rigid balls; `--open-menu` start with the settings menu open; `--no-echoes` / `--echoes` / `--rays` choose how fast parts are drawn; `--no-settings` ignore the saved settings file (screenshot runs already do); `--max-edge=<m>` mesh edge limit (a huge value turns tessellation off, handy for before/after shots).
- In-game keys: Tab settings menu (every option, see plan.md; H opens its Controls tab, which lists every key from `src/Ui/Keybinds.cs`, so add new bindings there); V camera mode (Fly: Space up, C down; Drone is FPV acro: W/S instant throttle (zero with no key), A/D yaw, mouse Y pitch, mouse X roll, gamepad sticks the same; Walk); P pause, `.` step one tick, `[` `]` time scale; left click throws a physics object (B next shape, X clear); F1 shader/CPU solve; F3 cycles debug text off / simple (profiler) / full (plus the debug view), saved to `user://debug_mode.cfg`; 1/2/3 toggle ghosts/rings/labels in full mode, saved to `user://debug_view.cfg`; mouse wheel or Up/Down arrows step c; WASD/QE/Shift fly; the mouse is locked, Esc frees it and the next click re-locks.
- For a clean screenshot without debug clutter, write `user://debug_view.cfg` (under `%APPDATA%/Godot/app_userdata/Lightspeed/`) with `ghosts/rings/labels=false`, then delete it afterwards so the user's settings are untouched.

## Rules and gotchas

- **Time:** only `SimClock` owns time (fixed 60 Hz tick). Never use wall-clock time or `delta` for simulation state. Reduce motion phases in `double` (`t % Tau`) before narrowing to float.
- **Tick order** relies on `ProcessPhysicsPriority`: SimClock −1000, movers 0, LightHistory 1000, HistoryTexture 2000. Keep new movers at the default.
- **Solver and shader are twins.** `RetardedSolver.cs` and `shaders/delayed_visual.gdshader` implement the same algorithm; change both together and keep the unit tests passing. Texture layout constants (`Chunk`, `TickWrap`) are duplicated in the shader.
- **Debugging shaders:** `return` is not allowed in `fragment()`; paint debug colours (EMISSION) and read the PNG with PIL instead. Remove experiments before finishing.
- **Time control lives in `SimClock`:** never use `Engine.TimeScale` alone (it only scales the physics delta; ticks keep coming at 60 Hz). `SetTimeScale` sets `Engine.PhysicsTicksPerSecond = 60 s` together with `Engine.TimeScale = s`. Pause is the tree pause: a node that must run while paused (camera, UI, anything in `_Process` that reads the camera) needs `ProcessMode = Always`, and an Always node with a `_PhysicsProcess` must return when `GetTree().Paused`. `HistoryTexture` advances once per tick, so ticks and physics must stay 1:1; never freeze mid-tick (`SimClock` defers it to `_Process`).
- **History length** is `GameSettings.HistorySeconds` and changes live: `HistoryTexture.Resize` re-packs every sample by age and calls `HistoryTrack.Resize`. Anything that caches the capacity must refresh on `HistoryTexture.Resized`; `--history=<s>` sets it for a run.
- **Submodule `libs/p2p-signaling-server`:** the signaling server repository, pinned to a commit. Its client library sources are compiled **into this assembly** by `Lightspeed.csproj` (`<Compile Remove="libs/**" />` then `<Compile Include="libs/.../clients/godot-csharp/src/**/*.cs" />`). Never use a `ProjectReference` or package for it: Godot only runs script classes (and their `_Process`) from the game assembly, so a separately compiled `P2PLobby` silently does nothing. Never edit files under `libs/` from this repository: change the server repository, push, then `git submodule update --remote libs/p2p-signaling-server` and commit the new pointer. Clone with `--recurse-submodules` (or run `git submodule update --init`); CI checks out submodules; `libs/.gdignore` keeps Godot from scanning it; the build scripts stop if it is missing.
- **Multiplayer (`src/Net`):** the full explanation of how the library is used (wiring, rules, what to replicate, troubleshooting, adding a game on the server) is `libs/p2p-signaling-server/docs/integration-guide.md` in the submodule; read it before changing the networking, and do not duplicate it here. This game is the guide's reference implementation. A host and clients over WebRTC through the p2p-signaling-server (bucket `lightspeed`; the server address is a setting, the room code is shared out of band). `NetSession` (autoload) owns the lobby, the roles and every RPC. The host is authoritative: it runs the physics and owns the shared settings, clients send their camera pose and their requests (speed of light, time scale, pause, throw) and follow what the host sends. Rules that keep it working:
  - **Assign the multiplayer peer in `P2PLobby.PeerCreated`, never later.** A peer attached to `Multiplayer` after it connected is never registered and its RPCs are dropped (`!connected_peers.has(sender)`).
  - **Scripted movers use `SimClock.WorldTime`, not `Time`.** Clients adopt the host's world time (`WorldOffset`), so movers match without replication. Ticks and the light history stay local; never jump `Tick` (the history texture advances once per tick).
  - **Other players are delayed parts** (`RemoteAvatar`): a node, `LightHistory`, ghost and `DelayedVisual` per piece, with poses from the network instead of a mover. Latency adds to the light delay.
  - **Physics bodies:** scene bodies are direct children of the scene root in group `net_body` (ids by sorted name); balls and thrown objects are announced by the host (`NetSession.OnBodySpawned`) and are frozen puppets on clients. A client's throw goes through `RequestThrow`. Anything new that must be networked needs the group or an `OnBodySpawned` call, and a scene listed in `NetSession.KindScenes`.
  - **Shared settings go through `SimClock`'s public setters,** which a client turns into requests to the host; the `Apply...` methods are what change the clock.
  - The game version sent to the server is the release tag without `v` (from `version.txt`), or `dev` from source; the bucket's `accepted_versions` must list it.
  - Dev options: `--net-url=`, `--net-name=`, `--net-host`, `--net-join=CODE`, `--net-cam=x,y,z,yawDeg,pitchDeg`, `--net-throw=N`, `--net-step-c=INDEX`, `--net-report-at=TICK`, `--net-report-paused` (print a report once the world has been paused 2 s), `--net-quit-at=TICK`, `--net-version=`. To test locally run two headless instances against a signaling server (a memory-store dev server built from the server repo works): host with `--pause-at-tick=N --net-report-paused`, join with `--net-join=CODE --net-report-paused`, and compare the `NET REPORT` / `NET BODY` lines.
- **Spawn/despawn** objects through `LightHistory` (`Despawn()`), not `QueueFree` on the body, so the visual outlives it; teleport with `BreakNext()`.
- **Bodies:** every object in the world has a physics body at its true position (the visual is delayed, the collision is not, so you bump into where the ghost is). Scripted movers (`Orbiter`, `Oscillator`, `Teleporter`, `CircleMover`) are `AnimatableBody3D` with `sync_to_physics` OFF (with it on, assigning `Position` from `_PhysicsProcess` is ignored and the body never moves), so the player and thrown objects collide with them and are pushed by them. Anything without scripted movement is a `RigidBody3D` with a `SpeedLimiter` (balls, thrown objects, the standing fan). Only the ground is static. A rigid object's every visible piece is a delayed part, never a plain mesh. New objects need collision shapes.
- **Parts:** a `DelayedVisual` ignores its own node transform, so every independently moving piece is a part (`Node3D` + `LightHistory` + ghost + `DelayedVisual`) offset through the part's transform. Compound machines (car, helicopter, fan) nest parts. Keep every part's peak speed (parent motion + spin x radius) below c.
- **Menu width is fixed:** every menu label and value is `ClipText` with a fixed minimum width; a new control must not let long text widen the panel. Menu sections are tabs (`Section` starts one, `SubSection` is a heading inside it).
- **Settings:** add a persisted option in `GameSettings` (default, load, save), a control in `SettingsMenu` (it refreshes from the getter, so hotkeys stay in sync), and have the consumer react to `GameSettings.Changed`. Scripted runs ignore the saved file. Controls use `FocusMode.None` so Space/WASD never trigger them.
- **Edges only warp if they have vertices:** `DelayedVisual` tessellates primitive meshes to `MaxEdgeLength`; non-primitive meshes are not tessellated (they log a warning).
- `SimClock.C` changes live (steps in `SpeedLadder`); read it each time, never cache it. Parts below c use the single-image binary search; parts at or above c are drawn as several images (`DelayedVisual.MaxImages`) via `find_image` in the shader and `RetardedSolver.SolveImage` on the CPU. Keep demos honest: a part's real speed is never reduced to hide this.
- **Fast-part rendering has three modes** (`GameSettings.FastParts`): one image (tears), Light Echoes (vertex copies, unreliable close to a part) and Exact rays (default; per pixel, primitives only, falls back to echoes otherwise). `RetardedRay.cs` and `delayed_ray.gdshader` are twins like the solver and the vertex shader; both include `lc_common.gdshaderinc`.
- **Ray intervals:** `RetardedRay.Intervals` runs on the CPU every frame per fast part and is uploaded as `iv_count` / `iv_sphere` / `iv_k` (16 slots). Its sample indices are track-relative; `DelayedVisual.UploadIntervals` shifts them to the shared texture window. The shader must only march inside them: anything outside is invisible by construction, and a test enforces that no ray hit falls outside.
- **Ray shader materials must stay `blend_mix`:** an opaque material that writes `DEPTH` goes through the depth pre-pass, which runs the march twice and drops pixels where the two runs differ by a hair (single-pixel speckles).
- **Multi-image details:** the shader is `cull_disabled` (reversed-orientation images), invalid vertices are discarded in the fragment stage through the `img_valid` varying, and `MAX_SCAN` in the shader equals `RetardedSolver.MaxScanIterations`.
- **Export builds must disable the .NET compiler servers** (`UseSharedCompilation=false`, `MSBUILDDISABLENODEREUSE=1`, set in `build.ps1` / `build.sh`): Godot waits for the .NET build's output pipe to close and the servers hold it for about ten minutes, so each export otherwise appears to hang. Run exports through the scripts, not by calling Godot directly from a pipeline.
- The Godot csproj has no implicit usings (add `using System;`). `Compile Remove="tests/**"` keeps test files out of the game assembly.
- In `.tscn` files, an `[Export]` that references a node needs `node_paths=PackedStringArray("Prop")` on that node's header, or it loads as null.
- If the Godot editor is open it may re-save `.tscn` and `project.godot` (adds uids, drops default values such as the 60 Hz tick); re-read a file before editing it.
- Shader globals (`lc_*`) are registered at runtime by `HistoryTexture`, so the editor may flag the shader until the game runs.
- Visuals are top-level, cast no shadows (until M7), and rely on a huge `CustomAabb`.
- Godot labels render a Windows CR+LF as a blank line: build multi-line text with `\n`, not `StringBuilder.AppendLine`.
- Profiler physics-time is a noisy single-step sample; trust the `history update` ms in the debug panel for our own cost.
- Don't commit `.godot/`, `bin/`, `obj/` (already in `.gitignore`).
